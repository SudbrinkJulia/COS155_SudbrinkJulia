Week 1 Reflection

Before refactoring, some of the most noticeable issues were repeated code and vague function names. In `EmotionEngine`, both `provideStimulus()` and `runCycle()` had separate checks to keep emotional values between 0 and 100. In `SystemCore`, `viewState()` and `runDiagnostics()` repeated code for displaying the emotional values and score status. Names such as `runCycle()` and `addLog()` also did not fully explain what each function did, which made the code harder to follow and maintain.

The biggest improvements were adding `clampEmotionValues()` in `EmotionEngine` and sharing the `displayEmotionalState()` and `displayAscensionStatus()` functions in `SystemCore`. I also renamed the methods to `applyStimulus()`, `advanceEmotionalCycle()`, `processStimulus()`, and `runEmotionalCycle()`, and renamed `logs` to `systemLogs`. These changes made the purpose of the code clearer and reduced duplicated logic. I updated the related calls in `Main.cpp` while keeping the existing menu options and program features.

One challenge was making sure the renamed functions matched in the header files, source files, and calls from `Main.cpp`. After the changes, the project built without errors. I ran the program and checked the state report, stimulus, emotional cycle, diagnostics, logs, and Ascension Trial; the score changed as expected and the trial passed when the score reached 130. If I had more time, I would add automated tests for score calculations and the 0–100 limits, and look at separating console output from system logic so those parts could be maintained independently.
